# 코드 미디어아트 퀄리티 기준 (2026-10-21)

오늘은 봄날 · 상상연필의 코드 작품은 모두 이 기준으로 만든다.
첫 적용: 「流帶 · 결결 II」 (`works/_source/flowribbons-gl.html`). 같은 시드로 1판과 나란히 비교함. 영상은 `디자인 시안/결결-비교-위전-아래후.mp4`.

## 왜 기존 작품이 "아마추어처럼" 보였나

기존 4편과 스튜디오 엔진 99종은 전부 Canvas2D 로 그린다. 그래서 다음 문제가 생긴다.

| 증상 | 원인 | 결결 1판에서 실제로 보인 것 |
|---|---|---|
| 빛이 겹친 곳이 하얗게 납작함, 색이 날아감 | `lighter` 가 255에서 잘린다 | 리본 교차점이 흰 떡 |
| 선에 구슬(점선) 무늬 | 선분마다 따로 그어서 마디가 두 번 더해진다 | 확대하면 모든 리본이 점선 |
| 겹친 색이 탁함 | sRGB 값을 그대로 더한다 (물리적으로 틀림) | 파랑+빨강이 회보라 |
| 어두운 그라데이션이 계단 | 8비트 저장, H.264 에서 더 심해짐 | 배경 글로우 띠 |
| 글로우가 "포토샵 외부광선" 같음 | 같은 선을 굵게 한 번 더 그은 가짜 번짐 | 헤일로가 균일한 두께 |
| 움직임이 끊겨 보임 | 프레임마다 한 순간만 찍는다 | 빠른 펄스가 깜박임 |

## 표준 파이프라인: `works/lib/bomnal-gl.js`

```
장면(선형 빛, RGBA16F, 더하기) → 다층 번짐(6단, 문턱 없음) → 노출 → AgX 톤매핑
→ 색보정(채도·대비·lift/gain) → 비네트 → 그레인(중간톤만) → 삼각 디더 ±1/255 → sRGB
```

- **색은 언제나 `BomnalGL.hex('#...')` 로 받는다.** 이 함수가 선형값으로 바꿔 준다. 색을 섞을 때는 `mixOklab`.
- **세기는 1을 넘어도 된다.** 오히려 넘겨야 한다. 1을 넘는 곳만 번짐이 피고 톤매퍼가 흰빛으로 눕힌다.
  색은 심이 아니라 번짐 쪽에 산다. 실제 빛이 그렇다.
- 선은 `G.ribbon(pts, col, inten(u), width(u))` 로 그린다. 이어진 띠로 그리고 해석적 AA를 쓰므로 구슬 무늬가 없다. 1px보다 가는 선은 밝기를 줄여 에너지를 맞춘다.
- 점은 `G.point(x, y, col, I, r)` 로 그린다. 가우스 점이고, 반지름이 1px 아래면 에너지를 보존한다.
- 배경과 장(field)은 `G.background(glslSource, uniforms)` 로 그린다. 반드시 `uGain` 을 곱한다.
- 모션블러는 `G.shutter(k, draw(sub))` 로 건다. 미리보기는 k=1, 납품 렌더는 k=6~16, 셔터 180°.

### 기본값 (결결 II에서 맞춘 값)
`exposure 1.0 · bloom 0.07 · tone 'agx' · sat 1.2 · contrast 1.1 · vignette 0.4 · grain 0.014`

결결 II에서 실제로 틀렸던 것:
- **배경 글로우를 선형으로 옮기면 훨씬 세진다.** 1판 값의 1/5~1/10 로 낮춰야 했다.
- **먼지 입자가 많으면 바로 "화면보호기 별밭"이 된다.** 1080p 기준 700개, 세기 0.1~0.6 정도로 아주 옅게 둔다.

## 움직임 (화면보호기처럼 안 보이게)

1. **흐름장:** 순수 펄린 노이즈를 그대로 쓰지 않는다. curl(발산 없는 흐름), 도메인 워핑(IQ), 장애물·끌개처럼 구조가 있는 장을 쓴다.
2. **적분:** 오일러 말고 중점법(RK2)을 쓴다. 보폭은 화면 폭의 0.1~0.5%.
3. **위계:** 큰 흐름 하나, 보조 흐름 하나, 미세 질감 하나.
4. **속도와 빛을 묶는다:** 빠르면 밝고 따뜻하게, 느리면 어둡고 차게. 태어나고 사라질 때 툭 튀지 않는다.
5. **루프:** 모든 주기가 길이 T를 나눠떨어지게 한다. 입자 수명은 `frac(k·p + off)` 처럼 엇갈리게 둔다. 노이즈는 원 위에서 샘플링한다(4D).
6. **극의 흐름:** 30~120초 안에 쌓이고, 터지고, 쉬는 구간을 둔다. 균일한 평형 상태로 계속 돌지 않는다.

## 색

- 주조 색 계열 하나, 무채색 하나, 포인트 색 하나. 넓이로 60 / 30 / 10.
- 무지개 hsl 회전은 금지. IQ 코사인 팔레트는 c ≤ 0.5, b 0.2~0.35 로 좁게 쓴다.
- **흑백으로 바꿔도 구도가 읽혀야 한다.** 화소의 대부분은 아래 20~30% 밝기에 있고, 초점 몇 곳만 밝게.

## LED · 프로젝션 납품

- 실제 LED 화소 지도(예: 2064×1032, 3840×1080) 그대로 렌더한다. 늘리거나 줄이지 않는다.
- 가장 작은 요소도 LED 2~3화소 이상. 4화소보다 촘촘한 반복 무늬는 모아레가 생기므로 금지.
- 평균 밝기를 낮게(15~35%) 유지한다. 전면 흰 화면은 금지. 밝음은 작은 하이라이트에만 둔다.
- 어두운 쪽 디테일은 신호 3~5% 이상으로 올리고 디더를 넣는다. LED 프로세서가 어두울 때 계조를 잃기 때문이다.
- 32:9는 가로로 흐르는 움직임을 쓰고, 프로세서 이음매인 정중앙을 피한다. 9:16은 오르내리는 움직임을 쓰고, 초점은 위쪽 1/3에 둔다.
- 코덱:
  - 마스터: ProRes 422 HQ
  - LED 송출: HEVC 10bit (`-pix_fmt yuv420p10le`)
  - 웹·시사: H.264 `-crf 14~16 -tune grain`

## 렌더

```bash
python3 -m http.server 4737     # 사이트 폴더에서
node tools/capture-frames.mjs "http://localhost:4737/works/_source/<작품>.html?capture=1&qual=1920&fps=30" out/f 0,1,2,...
python3 tools/rgba2png.py out/*.rgba
ffmpeg -framerate 30 -i out/f-%05d.png -c:v libx264 -preset slow -crf 16 -tune grain -pix_fmt yuv420p out.mp4
```

머리 없는(headless) 크롬은 소프트웨어 GL이라 느리다. 1080p 하위프레임 6장 기준으로 프레임당 약 0.35초. 4K 납품은 밤에 돌린다.

## 마무리 검사 — 각각 껐다 켜 보고, 무엇이 좋아지는지 말 못 하면 뺀다

- [ ] 선에 구슬·마디가 없다 (200% 확대해서 확인)
- [ ] 겹친 곳에 색이 남아 있고 하얀 떡이 없다
- [ ] 어두운 그라데이션에 계단이 없다 (인코딩한 mp4로 확인)
- [ ] 흑백으로 바꿔도 구도가 읽힌다
- [ ] 첫 프레임과 마지막 프레임이 이어진다
- [ ] 그레인이 1080p 원본에서 겨우 보이는 정도다
- [ ] LED 화소 지도와 최소 요소 크기를 지켰다
